# 多语菜单安全译审

入境旅游平台让菜品翻译、食材和过敏原说明经过来源可查的审定，避免出现
“译文只讲了菜名和文化故事，却没提示共用炸锅、当天又换过食用油”这类问题。

`fixtures/menu_claim.json` 保存一条经过脱敏的业务样例（椒盐鱿鱼：共用
炸锅存在花生/鱼交叉接触，炸制用大豆油，当天上午换油；另有季节替换与
午市售罄样例）。

## 角色边界

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| 餐厅（商户） | 以 `menu_claim.json` 声明原料、加工助剂、交叉接触、供应批次，并确认当前经营事实（换油、售罄） | 不写安全结论 |
| 译者 | 译文语义；机翻只能作为待审候选，译者签署后才生效 | 不判断过敏原 |
| 营养专业人员 | 复核过敏原与交叉接触风险，撰写带时效的目标语提示 | 不碰翻译、不碰配方明细 |
| 平台 | 身份匹配、发布唯一公开版本、缓存失效传播、游客展示 | 不向竞争商家公开配方 |

## 模块

- `claims.py` — 菜单声明合同：菜品与 `(recipe_id, recipe_version)` 配方
  标识、原料、加工助剂、交叉接触、供应批次、经营事实（带生效时间窗）。
- `identity.py` — 原图 SHA-256 指纹与拍照识别；置信度不足、一菜多名歧义
  时返回 `reasons`，不产出确定匹配。
- `translation.py` — 翻译链：`mt → post_editor → translator` 逐跳哈希，
  机翻候选不含任何安全字段，译者 HMAC 签署后为 `translator_signed`。
- `review.py` — 不确定闸门与三方签署。季节替换生效、识别不确定时复核包
  为 `blocked`；商户确认售罄时定稿为 `sold_out`（不附安全结论）；风险结论
  绑定配方版本、声明修订号、经营事实快照与时效。
- `publishing.py` — 公开版本注册表：同菜单反复拍摄只指向一个确认版本；
  公开载荷不含配方标识与批次（配方仅以短指纹参与绑定）；绑定变化必须走
  紧急更正，不能静默覆盖。
- `caching.py` — 多层缓存（app/edge/device 等）失效传播；逐层记录实际
  失效时间，最慢一层未回执前传播不算完成。
- `guest.py` — 游客收藏快照的有效性标注（`valid / expired / superseded /
  removed`）与带时效的追问回答；失效时只给说明性答复。
- `audit.py` — 复盘材料：原图指纹、配方版本、完整翻译链、三方签署、
  失效事件与实际失效时间、收藏内容现状。

## 状态与迁移

复核包：`draft → ready →（事实或版本变化）→ stale`；任一不确定情形为
`blocked`；商户确认售罄为 `sold_out`。公开版本：`active → corrected /
withdrawn`。

- 旧的最小合同读取器（`contracts.load_record`）忽略未知键，扩展后的样例
  仍可读；新状态只新增不重用语义，旧代码遇到未知状态必须保守处理，不得
  当作有效结论展示。
- 配方任何变化都必须提升 `recipe_version` 并提升声明 `revision`；绑定旧
  版本的签署在定稿时被拒绝，已发布内容只能通过紧急更正替换。
